# ADR 0002: Authentication, Password Hashing & Session Management

## Status
Accepted

## Context
CaseVault stores sensitive forensic records. Authentication mechanisms must prevent credential stuffing, offline brute-force cracking, account enumeration, timing attacks, and session hijacking. Ad-hoc hashing algorithms (e.g., raw SHA-256, MD5) or weak parameters are unacceptable.

## Decision
1. **Password Hashing**:
   - Enforce **Argon2id** password hashing via Spring Security `Argon2PasswordEncoder` backed by BouncyCastle (`bcprov-jdk18on`).
   - Parameters:
     - Memory cost: 65,536 KiB (64 MiB)
     - Iterations: 3
     - Parallelism: 1 lane
     - Salt length: 16 bytes (cryptographically secure random)
     - Hash length: 32 bytes
2. **Anti-Brute Force & Account Lockout**:
   - Account locks after 5 consecutive failed login attempts for 15 minutes.
   - Authentication errors return generic HTTP 401 response: *"Invalid username or password"*.
   - Timing equalization: for unknown usernames, execute a dummy Argon2id verification with a pre-computed hash to prevent response-time enumeration.
3. **Session Management**:
   - Server-side sessions with session fixation defense (regenerate session identifier on authentication).
   - Invalidation of existing sessions upon logout.
   - Cookie flags: `HttpOnly`, `SameSite=Strict`, `Secure` (in HTTPS profile).
   - Idle timeout: 15 minutes. Absolute timeout: 8 hours.
   - Disabled/revoked user accounts immediately terminate active sessions upon the subsequent HTTP request.
4. **First-Run Secret Bootstrap**:
   - Initial administrator password and encryption keys generated dynamically at first application start into git-ignored `.local-data/` or `secrets/`. Never stored in source code, logs, or Git history.

## Consequences
- **Positive**:
  - Memory-hard Argon2id resists GPU/ASIC offline attacks.
  - Uniform timing and generic errors eliminate account enumeration.
  - Strict cookie flags prevent XSS session exfiltration and CSRF.
- **Negative / Trade-offs**:
  - High memory cost (64 MB per hash calculation) requires intentional server CPU/memory provisioning.
