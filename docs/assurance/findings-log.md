## Lessons

- **F-001:** controls must be tested through the real entry point, not only the component. A unit-level call to the provider passed while the assembled HTTP path behaved differently.
- **F-002..F-006 (Phase 8B):** the header audit and the real-HTTP error tests found five issues that no component test had: an unknown URL answered 500, framework text in a 400 page, a missing audit event for the auditor, and an inconsistent 403. They were visible only through the real entry point (a browser-like request through the full filter chain and the container error dispatch).
- **F-007 (Phase 8C):** a setting that is configured but never exercised can be dead. The cap property existed only after a test showed the oldest session still working; the cause was a missing `equals` on the principal.
- **F-008 (Phase 8C follow-up):** tests that commit data share one database for the whole run. A green build in one run order proves nothing about another; run `-Dsurefire.runOrder=reversealphabetical` before relying on test isolation, and clean up dependents before parents.
- **F-009 (Phase 9B):** a status word on screen must be computed from the same source as the real check, or be a description without a status. Constants that look like live status are worse than no status.
- **F-010 (Phase 9B):** assertions on link targets found URL rewriting (`;jsessionid`) on an error page; write link tests so that they show such surprises instead of hiding them.

- **F-010 update (fixed, follow-up to Phase 9B):** Cause: Tomcat default session tracking includes URL rewriting; a client without a session cookie that triggers a response through the error dispatch (signed-out CSRF 403 page) got `;jsessionid=<id>` on every encoded link (stylesheet, login link). Measured before the fix with real HTTP: only the signed-out CSRF 403 body had it; `/login`, the redirect to `/login` and the login redirect did not. Fix: `server.servlet.session.tracking-modes=cookie` in `application.properties` (all profiles inherit it); no other change was needed. Residual risk: none known for URL tracking; cookie flags are unchanged (HttpOnly, SameSite=Strict, Secure on prod-like); browser behaviour VERIFY MANUALLY. Retest: `.\mvnw.cmd -B test "-Dtest=SessionIdInUrlHttpTest,ErrorPageLinksHttpTest"`.
